# Cooperation, Competition & Coordination



多主体的核心困难是彼此行为会改变环境。先区分合作、竞争与混合关系，再讨论协调目标。

## 合作与竞争的收益结构

- **Cooperation**：主体目标高度一致。
- **Competition**：主体收益相反或存在资源冲突。
- **Mixed motives**：既合作又竞争。
- **Coordination**：让行动在时间、空间或资源上相容。

## 协调问题的基本形式

合作不等于自动协调。即使所有 agent 奖励相同，如果各自观测不同、通信受限、行动存在耦合，也可能发生冲突。

协调的核心是减少联合行动中的不一致，而不是强行追求完全相同的动作。

## 冲突、资源与共同目标

- Role assignment：不同 agent 承担不同角色。
- Convention：预先约定冲突解决规则。
- Coordination signal：共享少量关键信息。

## 可执行的协调机制

两台车都想帮助团队，但如果同时去搬同一个已经被拿走的物资，就会重复劳动；问题是协调，不是“缺乏合作意愿”。

## 协调失败诊断

多智能体冲突经常来自信息、规则或目标没有对齐。例如两台车同时去拿同一物资，可能不是规划器能力不足，而是系统根本没有“目标占用”这一共享状态；两个 Agent 反复抢同一任务，也可能是缺少确定性的冲突消解规则。

工程上应先依次检查：是否知道彼此正在做什么、是否有统一优先级、是否能检测冲突、冲突后是否有重新分配机制。只有这些机制仍不足时，才需要更复杂的优化或学习算法。

## 协调机制通常由占用、优先级、冲突处理组成

以两台机器人争抢同一任务为例，一个足够简单的工程机制可以是：任务先被声明为 `free`，机器人提交占用请求；若同时请求，则按距离或固定 ID 决定赢家；失败者立即重新选任务。这里没有复杂 MARL，但已经解决了大部分重复劳动。

这种机制的关键不是某个具体规则，而是**所有参与者对规则有共同理解**。若机器人 A 按距离排序、机器人 B 按剩余电量排序，即使二者都“很智能”，系统仍会反复冲突。

## 集中协调和分散协调只是信息位置不同

中心节点拥有全局状态时，可以统一分配任务；完全分散时，各 Agent 需要通过局部通信或公共规则形成一致决定。二者没有绝对优劣：中心化实现简单但有单点依赖，分散式更鲁棒但协议更复杂。实际系统常采用混合方式——中心给高层任务，局部机器人自行避障和恢复。

## 协调协议需要终止条件

一个协调过程不仅要规定如何提出方案，还要说明何时确认、超时后怎样处理、冲突时谁拥有优先权。没有终止条件的协商可能在动态环境中持续追赶旧状态。工程协议通常宁可接受次优方案，也要在明确时间内给出可执行决定。
