# Agents & System Architectures

单个 Agent 只需要考虑"环境怎样响应我的动作"；多个 Agent 同时决策后，**别人的动作也会改变我的结果**。多智能体系统真正增加的不是"多几个程序"，而是耦合、局部信息与协调问题——这三件事决定了后面所有章节的难度来源。

## MDP 与 Markov Game

先固定单智能体的符号，否则后面无法说清"哪里变了"。单智能体 MDP 是五元组 $(\mathcal S,\mathcal A,P,r,\gamma)$，转移写成

$$P(s'\mid s,a).$$

$s$ 是环境状态，$a$ 是唯一决策者的动作，$P$ 只依赖这两个变量。有 $n$ 个主体时，动作从标量变成联合动作向量：

$$\mathbf a=(a_1,\dots,a_n),\qquad a_i\in\mathcal A_i,$$

转移随之变成

$$P(s'\mid s,\mathbf a).$$

奖励也不再唯一。每个主体可以有自己的奖励函数

$$r_i=\mathcal R_i(s,\mathbf a,s'),$$

于是同一个状态下，主体 $i$ 的动作好不好，不只取决于 $a_i$，还取决于其他主体的 $\mathbf a_{-i}$（除 $i$ 之外的联合动作，属于 $\mathcal A_{-i}=\prod_{j\neq i}\mathcal A_j$）。**这就是多智能体问题的第一层本质：决策相互耦合。**

耦合带来的直接后果是"最优"这个词失效。单智能体里可以定义 $V^{\star}(s)=\max_a Q^{\star}(s,a)$，多主体里必须改写为依赖他人策略的量：

$$V_i^{\pi_i,\pi_{-i}}(s) = \mathbb E\!\left[\sum_{t=0}^{\infty}\gamma^{t} r_i(s_t,\mathbf a_t)\;\Big|\; s_0=s,\; a_{i,t}\sim\pi_i,\; a_{j,t}\sim\pi_j\right].$$

上标 $\pi_{-i}$ 是关键：**Agent $i$ 的价值函数本身是其他人策略的函数**，不是环境的属性。这解释了为什么多智能体系统里"一个策略到底好不好"必须连同"在什么对手/队友配置下"一起说。

| 概念 | 单智能体 | 多智能体 | 带来的新问题 |
|---|---|---|---|
| 动作 | $a\in\mathcal A$ | $\mathbf a\in\prod_i\mathcal A_i$ | 空间指数增长 |
| 转移 | $P(s'\mid s,a)$ | $P(s'\mid s,\mathbf a)$ | 他人动作进入动力学 |
| 奖励 | $r(s,a,s')$ | $r_i(s,\mathbf a,s')$ | 目标可能冲突或共享 |
| 最优性 | $\max_a$ 有定义 | 依赖他人策略 | 需要均衡概念 |
| 观测 | $s$ 通常可知 | 通常只有 $o_i$ | 需要通信或记忆 |
| 稳定性 | 环境固定 | 他人策略持续变化 | 非平稳性 |

## Markov Game 的联合动作空间

Markov Game（又称随机博弈）是 MDP 的多主体推广，写成 $(\mathcal S,\{\mathcal A_i\}_{i=1}^{n},P,\{\mathcal R_i\}_{i=1}^{n},\gamma)$。它的状态转移与奖励都作用在**联合动作**上：

$$P:\mathcal S\times\mathcal A_1\times\cdots\times\mathcal A_n\to\Delta(\mathcal S),\qquad \mathcal R_i:\mathcal S\times\mathcal A_1\times\cdots\times\mathcal A_n\times\mathcal S\to\mathbb R.$$

联合动作集合的大小是各 Agent 动作数的乘积：

$$\big|\mathcal A_{\text{joint}}\big| = \prod_{i=1}^{n}\big|\mathcal A_i\big|.$$

在同构情形（每个 Agent 都有 $m=|\mathcal A_i|$ 个动作）下就是 $m^{n}$。这个数字的可怕之处在于它是**指数**，而不是线性。下表给出 $m=3$ 时的增长：

| Agent 数 $n$ | 联合动作数 $3^{n}$ | 若每组合需 1000 次采样 | 直观类比 |
|---|---|---|---|
| 1 | 3 | $3\times10^{3}$ | 单个路口信号灯 |
| 5 | 243 | $2.4\times10^{5}$ | 5 台仓库 AGV |
| 10 | 59 049 | $5.9\times10^{7}$ | 10 台无人机编队 |
| 15 | 14 348 907 | $1.4\times10^{10}$ | 中型车队长 |
| 20 | $3.49\times10^{9}$ | $3.5\times10^{12}$ | 城市级路口网络 |

即使把每个联合动作的价值估计压缩到 1000 次采样，$n=20$ 也需要 $3.5\times10^{12}$ 次环境交互；若每次交互 10 ms，串行总时长约 $1.1\times10^{4}$ 年。**结论不是"努力优化"，而是必须放弃枚举。**

可行的绕过方式有三类，它们的代价各不相同：

- **独立分解**：假设 $Q_i(s,\mathbf a)\approx Q_i(s,a_i)$，把联合空间压回 $n\cdot m$。代价是忽略耦合，在真耦合场景（抢路口、抢任务）上系统性失效。
- **参数共享 + 结构假设**：所有 Agent 用同一套参数，靠输入的身份或角色区分。代价是需要同构性，异构系统（车 + 无人机 + 人）难以直接套用。
- **集中训练 / 分散执行（CTDE）**：训练时用一个能看到全局信息的 critic 估计联合价值，执行时各 Agent 用自己的 actor。代价是训练与执行的信息结构不一致，若执行期观测不足则性能回退。

| 方法 | 复杂度量级 | 何时有效 | 何时失效 |
|---|---|---|---|
| 联合 Q 表 | $\mathcal O(|\mathcal S|\cdot m^{n})$ | $n\le 3$、动作少 | Agent 数一多直接爆 |
| 独立 Q 学习 | $\mathcal O(n|\mathcal S| m)$ | 耦合弱（主体分散） | 竞争/拥塞场景震荡 |
| 参数共享 | 参数量与 $n$ 无关 | 同构 Agent | 异构任务 |
| CTDE | 训练期 $\mathcal O(1)$ critic、执行期 $\mathcal O(m)$ | 训练可集中 | 部署时观测受限 |

## 局部观测让每个 Agent 看到的世界不同

现实系统里一个 Agent 往往只能拿到局部观测 $o_i$，而不是完整状态 $s$。例如仓库机器人知道自己位置与附近障碍物，却不一定知道其他机器人的当前任务；无人机看到自己视角的画面，却看不到墙后的队友。观测由观测函数生成：

$$o_i = \mathcal O_i(s, \mathbf a, \epsilon_i),$$

$\epsilon_i$ 是传感噪声。$\mathcal O_i$ 的**输出维度与内容各不相同**：激光雷达给 360° 距离序列，摄像头给图像，调度接口给一条任务 ID。这意味着几个概念必须分开：

| 概念 | 定义 | 例子 | 缺失时的后果 |
|---|---|---|---|
| state $s$ | 描述整个环境的真实变量 | 全部车辆位置与任务 | 无法定义全局最优 |
| observation $o_i$ | 主体实际拿到的信息 | 本车位姿 + 局部地图 | 决策依据不足 |
| message $m_{j\to i}$ | 其他主体主动传的信息 | 队友的意图、占用的路口 | 协调失败、死锁 |
| history $h_i$ | 到 $t$ 为止的观测动作序列 | $o_{i,0:t},a_{i,0:t-1}$ | 无法推断隐藏状态 |
| belief $b_i$ | 对 $s$ 的概率分布 | $P(s\mid h_i)$ | 无法做最优决策 |

判断"观测够不够"有个实用判据：若当前 $o_i$ 不足以决定下一步最优动作，且这不是传感精度问题而是**信息结构问题**，就必须引入记忆或通信。形式化地，若

$$I\big(a_i^{\star};\; s \mid o_i\big) > 0,$$

即最优动作与状态之间在给定观测后仍有剩余互信息，说明 $o_i$ 不是充分统计量。此时把一个单智能体算法复制 $n$ 份，只会得到 $n$ 个各自犯错的主体。

## 部分可观测与 Dec-POMDP 的信息结构

把"局部观测 + 完全合作"的组合形式化，就是 Dec-POMDP（去中心化部分可观测 Markov 决策过程）：

$$\big\langle \mathcal S,\; \{\mathcal A_i\},\; P,\; r,\; \{\mathcal O_i\},\; \mathcal Z,\; \gamma \big\rangle,$$

其中 $\mathcal Z(s,\mathbf a,o)$ 给出观测联合分布，$r$ 是共享的团队奖励。这里的困难不在于某个 Agent 学不会，而在于**信息分布本身**：每个 Agent 只见到自己的 $h_i$，却要联合起来最大化同一个 $r$。

信息共享程度是设计时最需要显式选择的维度，从"完全不共享"到"共享原始状态"，可用性和代价差异极大：

| 共享程度 | 每个 Agent 掌握什么 | 通信代价 | 适用场景 | 主要失效 |
|---|---|---|---|---|
| 无共享 | 仅 $h_i$ | $0$ | 大规模、弱耦合 | 协调死锁 |
| 共享意图 / 计划 | $h_i$ + 队友下一步目标 | 低（几字节） | 车队、编队 | 意图过期 |
| 共享局部总结 | $h_i$ + 邻居状态摘要 | 中 | 多机协同、部分耦合 | 摘要丢信息 |
| 共享全局状态 $s$ | 完整状态 | 高（全带宽） | 小规模、有中心节点 | 带宽/延迟不可行 |
| 共享全局状态 + 联合动作 | $s$ 与 $\mathbf a$ | 极高 | 仅训练阶段（CTDE） | 部署时无法满足 |

信息共享的收益可以用一个可计算的条件粗略描述：共享带来的回报增益，必须超过"消息占用资源 + 延迟导致决策过期"的损失。设消息延迟 $\tau$、决策周期 $\Delta t$，若 $\tau > \Delta t$，消息到达时决策窗口已关闭，此时共享不仅无用，还会因为等待而加剧不同步——**这正是"传得越多不一定越好"的机制解释。**

Dec-POMDP 的复杂度是 NEXP-complete，即使 $n=2$ 也是如此；因此实践中不会去精确求解，而是退化为三类近似：集中训练分散执行（CTDE）、显式通信协议学习、以及把协调规则写死成启发式或市场机制。

| 方法 | 对信息结构的要求 | 复杂度 | 用在哪一章 |
|---|---|---|---|
| CTDE | 训练期可访问 $s$ 与 $\mathbf a$ | 训练重、执行轻 | [多智能体学习](05-multi-agent-learning.md) |
| 显式通信学习 | 可交换消息 $m$ | 消息空间爆炸 | [通信与信息共享](03-communication.md) |
| 规则/市场机制 | 只需广播出价 | 低且可预测 | [任务分配](04-allocation-distributed-decision.md) |

## 多智能体学习的三类困难

### 3.1 非平稳性

主体 $i$ 学习时，其他主体的策略 $\pi_j$ 也在变化。即使物理环境完全不变，从 $i$ 的角度看，同一个 $(s,a_i)$ 对应的结果分布仍在改变：

$$P_t\big(s'\mid s,a_i\big) = \sum_{\mathbf a_{-i}} P\big(s'\mid s,\mathbf a\big)\prod_{j\neq i}\pi_{j,t}\big(a_j\mid o_j\big).$$

下标 $t$ 表示时刻——**环境对 $i$ 而言每步都在漂移**。这直接破坏经验回放的有效性：三个月前存入缓冲区的 $(s,a_i)$ 与它当时观察到的回报，是在一个已经消失的"他人策略配置"下采集的。固定目标网络、降低学习率等技巧只能缓解速度，不能取消漂移。

### 3.2 信用分配

完全合作时所有主体可能共享同一个团队奖励 $r$。但"奖励相同"不代表每个动作贡献相同。以一个 team reward 的形式写：

$$Q_{\text{team}}^{\boldsymbol\pi}(s,\mathbf a) = \mathbb E\Big[\sum_t \gamma^{t} r(s_t,\mathbf a_t)\Big],$$

它把 $n$ 个主体的动作揉成一个整体价值，梯度信号无法区分谁的关键动作带来了收益。三台机器人共同搬运，任务成功只给一个总奖励，就要面对这样的问题：是谁完成了关键动作，谁只是恰好在场？

可用的做法包括差分奖励（difference reward）：

$$D_i = G(\mathbf a) - G(\mathbf a_{-i}),$$

即"有我在"与"没我在"的收益差，它天然把"恰好在场"的贡献压到 0；还有反事实基线、按角色加权、以及分成任务级与个体级的奖励塑形。**判断指标很直接：如果替换某个 Agent 的策略为随机策略，团队回报几乎不变，说明它对回报没有实质贡献，也说明信用分配信号当前是模糊的。**

### 3.3 联合空间增长

如果每个主体有 $m$ 个动作，联合动作组合数量就是

$$\big|\mathcal A_{\text{joint}}\big| = \prod_{i=1}^{n}\big|\mathcal A_i\big|,$$

同构情形下约为 $m^{n}$（$m=3$ 时的具体数值见前文表格）。因此枚举全部联合动作会很快变得不可行，必须依靠分解、参数共享或集中—分散结构。

这三个困难——**目标在移动、奖励难归因、组合数量增长**——基本解释了为什么 MARL 需要额外结构，而不是把单智能体算法复制 $n$ 份。

| 困难 | 可观测征兆 | 缓解手段 | 未能缓解时的表现 |
|---|---|---|---|
| 非平稳性 | 回报曲线周期性震荡、复现性差 | CTDE、慢更新对手、冻结对手 | 训练不收敛、互相对抗升级 |
| 信用分配 | 团队奖励稳步上升但个体行为退化 | 差分奖励、反事实基线 | 出现"搭便车"的 Agent |
| 联合空间 | 采样效率随 $n$ 断崖下跌 | 分解、参数共享、结构假设 | 训练规模无法扩展 |

## Reactive、Deliberative 与 Hybrid

架构选择决定"决策在什么时间尺度上、基于什么信息发生"。三者不是代际更替关系，而是分别占据不同的时间尺度。

### 4.1 Reactive：看到什么就立即反应

反应式 Agent 是观测到动作的直接映射：

$$
\pi(o)=
\begin{cases}
\text{停止}, & d(o)<d_{safe},\\
\text{前进}, & d(o)\ge d_{safe}.
\end{cases}
$$

$d(o)$ 是观测中估计出的最近障碍距离，$d_{safe}$ 是安全阈值。优点是没有内部状态、结果可预测、延迟极低（通常一个控制周期内完成），适合避障与安全保护；缺点是缺少长期规划，容易陷入局部极小——例如在凹形障碍前反复"前进—停止"而不绕行。

### 4.2 Deliberative：先维护状态，再规划

慎思式 Agent 会维护内部世界模型，根据目标搜索动作序列，例如求解最短路径：

$$\pi_{\text{plan}} = \arg\min_{\text{path}} \sum_{k} \|\text{pose}_{k+1}-\text{pose}_{k}\|.$$

它适合任务级规划（去哪、按什么顺序做），但计算更慢，而且**依赖模型质量**：地图有一处未更新的障碍，规划出的路径就可能完全不可行。重规划周期通常是秒级，无法应对突发动态障碍。

### 4.3 Hybrid：高层规划，低层反应

现实机器人最常见的是混合结构，三层各自负责不同时间尺度：

| 层次 | 时间尺度 | 输入 | 输出 | 失效后果 |
|---|---|---|---|---|
| Mission / Planner | 秒—分钟 | 任务列表、全局地图 | 目标点序列 | 任务分配错误 |
| Local Controller | 毫秒—秒 | 目标点、当前位姿 | 速度/转向指令 | 轨迹偏差、超时 |
| Safety / Reactive | 毫秒 | 传感器原始数据 | 覆盖或急停 | 碰撞、人员受伤 |

高层的职责是"去哪、做什么"，低层负责"怎么稳定执行"，安全层负责在紧急情况下**覆盖上层命令**。这个覆盖关系是分层设计的核心：安全层必须拥有最高优先级，否则一旦上层规划出错，就没有任何机制能阻止它被执行。对应到 RL 语境，这一层就是训练后可选的运行时过滤器，与 [Safe, Robust & Offline RL](../reinforcement-learning/06-safe-robust-offline.md) 中的约束与兜底机制直接对应。

三种架构的取舍可以概括为：Reactive 用"信息少、延迟低"换可预测性；Deliberative 用"计算与建模成本"换长期最优；Hybrid 用"分层接口设计复杂度"换两者兼顾。

## 架构选择的判据

选择架构不是风格问题，而是三个可测量的量共同决定：任务的时间尺度、信息的可获取性、失效的代价。

把决策周期记为 $\Delta t$，感知与通信延迟记为 $\tau$，规划所需的前瞻步数记为 $H$。最基本的可行性条件是不等式

$$\tau + T_{\text{compute}}(H) \le \Delta t,$$

即"感知 + 计算"必须在下一个决策时刻之前完成。若 $H$ 大（需要长前瞻）而 $\Delta t$ 小，Deliberative 结构在物理上就不可能实现，必须降级为 Reactive 或者把长前瞻放到低频层。

| 任务时间尺度 | 信息可获取性 | 失效代价 | 推荐架构 |
|---|---|---|---|
| 快（$<100$ ms） | 仅局部传感 | 高（人身安全） | Reactive 安全层，规则优先 |
| 快（$<100$ ms） | 局部 + 低延迟邻居信息 | 中 | Reactive + 局部协商 |
| 中（0.1–1 s） | 局部 + 部分全局 | 中高 | Hybrid：反应层 + 局部规划 |
| 中（0.1–1 s） | 全局状态可得 | 中 | Deliberative 局部规划 |
| 慢（秒—分钟） | 全局状态可得 | 低—中 | Deliberative 全局规划 |
| 慢（秒—分钟） | 信息不全、Agent 众多 | 中 | 规则/市场机制 + 低频优化 |
| 任意 | 训练期全局、执行期局部 | 中高 | CTDE（训练集中、执行分散） |

三条经验判据：**时间尺度决定能否规划**（$\Delta t$ 太小则只能反应）；**信息可获取性决定协调方式**（拿不到全局信息就只能靠通信或规则）；**失效代价决定是否需要独立于主策略的兜底层**（代价越高，越不能把安全托付给学出来的策略）。三者中只要有一项是"高"或"不可得"，就应当保留非学习的安全层，而不是让单一学出的策略承担全部职责。

## MAS 建模要素

以多车任务分配为例，建模要按顺序回答五个问题，顺序不能颠倒——先定主体，才能定观测；定了观测，动作空间才有意义。

1. **主体是谁？** 每台车是否独立决策？还是由中央调度器统一指挥、车只是执行器？这决定了 $n$ 的取值与耦合程度。
2. **每个主体能看到什么？** 位置、任务、局部地图还是全局状态？对应观测函数 $\mathcal O_i$ 的内容与维度。
3. **动作是什么？** 移动、接受任务、等待、通信？动作集合的基数直接决定 $|\mathcal A_{\text{joint}}|=\prod_i|\mathcal A_i|$。
4. **目标是什么？** 总时间、能耗、安全，还是各自不同目标？共享目标对应完全合作，冲突目标对应竞争，混合则介于两者之间。
5. **哪些变量需要共享？** 当前任务、剩余资源、局部发现？这决定通信带宽需求与延迟容忍度。

每一条都可以量化到设计参数上：

| 建模要素 | 形式化问题 | 具体参数 | 设计影响 |
|---|---|---|---|
| 主体边界 | $n$ 取多少？ | Agent 数量与同构性 | 联合空间大小、是否可参数共享 |
| 观测 | $\mathcal O_i$ 的内容 | 传感器列表、通信范围 | 是否需要记忆/通信 |
| 动作 | $\mathcal A_i$ 的基数 | 离散动作数或连续维度 | 学习难度、协调粒度 |
| 目标 | $r_i$ 是否相同 | 共享/个体/竞争 | 均衡概念选择 |
| 共享变量 | 消息集合与频率 | 字节数、周期 | 带宽占用、延迟容忍 |
| 时间尺度 | 决策周期 $\Delta t$ | 控制环/规划环频率 | 架构分层方式 |

只要这五个问题没有明确，讨论通信协议、任务分配或 MARL 都是空谈——因为这些技术各自都以"观测结构""动作空间""目标结构"为输入假设。**建模要素不清楚时，最有效的动作是回到这五个问题，而不是换算法。**

## 一个仓库机器人例子

假设有 4 台 AGV 和多个搬运任务，构成一个典型的中等耦合系统。

- 每台车知道自己的位置、电量、当前任务，即 $o_i$ 是本车位姿 + 电量 + 任务 ID；
- 调度信息通过低带宽网络共享，带宽与延迟构成硬约束；
- 同一任务不能被两台车重复执行，即存在全局唯一性约束；
- 路口可能发生局部冲突，即存在物理耦合；
- 总目标是缩短完成时间，同时避免碰撞和电量耗尽，即回报 + 两类约束。

这个看似简单的场景里实际包含三个层次，混在一起谈必然失败：

| 层次 | 问题 | 时间尺度 | 典型手段 | 失败的典型症状 |
|---|---|---|---|---|
| Task allocation | 谁去做哪个任务 | 秒—分钟 | 拍卖/匈牙利算法/规则 | 任务重复执行或长期无人认领 |
| Coordination | 多车动作怎样避免冲突 | 0.1–1 s | 优先级、预约、局部协商 | 路口死锁、互相让行 |
| Navigation / control | 每台车怎样真正到达目标 | 10–100 ms | 局部规划 + 反应式避障 | 轨迹振荡、贴近障碍 |

分层的价值在于**可定位性**：出现"两台车堵在路口互相等待"时，能立刻判断这是 Coordination 层的问题，而不是去调低层控制器参数；出现"任务完成时间异常长"时，先查 Task allocation 是否把任务分给了电量不足的车。把三个层次分开，比直接说"做一个多智能体算法"更容易设计系统，也更容易定位失败发生在哪一层。各层的具体方法分别在 [任务分配与分布式决策](04-allocation-distributed-decision.md) 与 [路径与运动规划](../robotics/04-path-motion-planning.md) 中展开。

## 系统边界决定谁算 Agent

并非每个软件模块都应被视为独立 Agent。判据是三条同时成立：拥有**自己的观测**（信息输入不同于别人）、**自己的动作**（能独立影响环境）、**自己的决策目标**（有独立优化的对象）。三条全满足，把它建模为 Agent 才有分析价值。

形式化一点：若模块 $i$ 的动作总能写成 $a_i = f_i(a_j)$（完全是另一个模块决策的确定性函数），那么 $\mathcal A_i$ 与 $\mathcal A_j$ 的维度信息是冗余的，把它们视为两个 Agent 只是把 $|\mathcal A_{\text{joint}}|$ 白白乘了一次。

| 情形 | 是否建模为独立 Agent | 理由 |
|---|---|---|
| 每台 AGV 自主决策路径 | 是 | 观测、动作、目标三者独立 |
| 低层 PID 跟随上层速度指令 | 否 | 动作为上层输出的确定函数 |
| 传感模块只提供数据 | 否 | 无动作、无目标 |
| 两个子系统各自有 KPI 且互不隶属 | 是 | 目标冲突需要均衡分析 |
| 同一控制器分时控制两个执行器 | 否 | 决策权未分离 |
| 人类操作员与自动车共用通道 | 是 | 观测、动作、目标都不同，且不可完全预测 |

误判会带来两个方向的代价。把不该拆的拆开：引入额外的通信与协调开销，$|\mathcal A_{\text{joint}}|$ 无意义膨胀，还可能因为"两个 Agent 只是同一个决策者的两只手"而出现人为的非平稳性。把该拆的不拆：把具有独立目标的子系统压成单一决策者，会掩盖真正的博弈结构，得到的策略在多主体共存时失效。

一条实用经验：**先按"谁能独立说不"划边界。**若某个组件可以在不违反上级指令的前提下拒绝一个动作，它实际上就拥有独立的决策权，应当被建模为 Agent；若它必须无条件执行，就属于同一个决策体的执行层。
