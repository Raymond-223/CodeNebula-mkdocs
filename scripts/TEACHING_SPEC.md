## 0. 这一版要解决什么

现在线上每一章的问题是：**像"查漏补缺 / 岗位说明书"**——它告诉读者"这个领域有什么、
为什么重要"，但没有带着一个零基础读者把任何一个知识点推一遍。读者读完知道"有这么些东西"，
但学不会其中任何一个。这一版要把每章改写成：**带着读者把一个知识点从现象推到结论**。

### 必须删掉的写法（当前线上写法，逐条对照删）

| 症状 | 长什么样 | 读者会怎样 |
|---|---|---|
| 岗位职责式开头 | 「XX 很重要 / 是核心 / 是最常见的 YY 之一」 | 不知道这是干什么用的 |
| 名词解释式主体 | 「XX 是 YY 的 ZZ」+ 方法名清单 | 记住名字，学不会任何一个 |
| 公式空降 | 先抛公式，再解释符号 | 只能背，不能重建 |
| 结论宣告 | 「注意 X 会带来 Y」「顺序不可颠倒」 | 知道结论，不知道边界 |
| 术语默认已知 | 首段就出现没拆开的术语 | 第一段就被劝退 |
| 只有收束没有过程 | 结尾给检查清单/表格，不给推演 | 无法迁移到新问题 |

## 1. 章节骨架（PID 章验证过的 9 步）

1. 读者**已经会做的**日常动作 → 从中拆出 N 条直觉 → 才给它们命名（先直觉，后概念）
2. 为什么非要造这个东西：最直接的办法为什么坏（推到它坏掉的具体场景）
3. 每个核心概念一节：现象 → 老办法为什么不够 → **这一项为什么被迫存在**（先推一遍）→ 生活类比 → 公式
4. 合成一条时间线/流程（起步→接近→越过→稳态），找出「谁在供电」这类现场证据
5. 完整公式 + 离散/实现形式 + 内部状态数量（集中汇总，不散落）
6. 工程选型/整定：顺序 + **为什么不能颠倒**
7. 可跑的最小实验（依赖最少）
8. 失败模式反查表：现象 → 最可能原因 → 先验证什么
9. 小结：2–3 句话回答「为什么必须有它 / 代价是什么」

## 2. 四条硬规矩

1. **结论必须推出来，不能宣告。**  例：不写"P 控制一定留残余误差"，而是先讲"输出为零时系统就后退（重力/摩擦）"→ 推出稳态必须用非零误差换非零输出 → 再补公式和数字。
2. **术语第一次出现当场拆开**（中英文都给），不留给读者去查。
3. **每个知识点配一个可验算的数字例子**，比一排形容词有说服力。
4. **公式位置**：每个知识点先直觉后公式；完整/离散形式集中到"汇总节"——前面几节可以零公式起步。

## 3. 硬性格式（check_docs.py 会查，违规会挂 CI）

- **H1 必须逐字等于 `mkdocs.yml` 里该页的侧边栏标签（英文）**。例：`# PID Principles`、`# Linear Algebra & Calculus`。不要改写、不要翻译。
- **H2 用中文、`## 一、…` 编号**，数量 4–16 个。H3 用 `### …`。
- **章节长度 200–520 行**（守卫上限 560）。
- **不要出现 tab 字符**；不要出现 `\*`（上标写 `^*`）；行内 `$` 必须成对，`$$` 必须成对。
- 禁用 H2 标题（会自动报错）：`## Why it matters`、`## Core ideas`、`## Key theory`、`## Representative methods`、`## Worked example`、`## Connections`、`## Further Reading`、`## Further Study`、`## Learning path`、`## 基本概念`、`## 核心原理`、`## 常用方法`、`## 一个简单例子`。
- **本地链接必须指向真实存在的文件**（用 `./NN-xxx.md` 相对路径）。写完结尾的过渡链接前，先 `ls` 确认目标文件存在。
- **原有图片引用一个字都不能删**：把旧的 `![...](../img/xxx.svg)` 行保留下来（可以挪位置、可以改周围文字），因为全站 47 张图必须每张都被引用。同一篇文章里不要重复引用同一张图。**不要新增指向不存在文件的图片路径**。
- 不要用控制字符。

## 4. 代码规则

- **理论章**（mathematics / game-theory / reinforcement-learning / multi-agent-systems / control-theory）：最多 **2 个**可跑示例，单个 python 代码块 ≤45 非空行。
- **工程章**（robotics / perception / distributed-systems / software-engineering / simulation-sim2real）：**保留原有代码块**（每章 2–20 个），可以增补到 20 以内。
- **所有代码块必须实跑过**，把真实 stdout 逐字贴回文档。没实跑的代码块**不要写"预期输出"**（宁缺勿假）。
- 优先**纯 numpy / 纯标准库**；**绝对不要用 matplotlib**（WSL 里 matplotlib.backends 常常是坏的）。要"看得见曲线"就用**终端 ASCII 曲线**：把序列采样到 N 列，按 `(ymax-v)/(ymax-ymin)*(rows-1)` 映射成字符网格，目标线用 `-` 回填其余列。
- 实验要留"改一个参数 → 现象突变"的钩子（收紧限幅 → windup 炸开；加噪声 → 某项把输出顶到限幅），并**打印反例**（一行"补上 X 仍然超调 23%"比一句断言强得多）。
- **从旧章节继承来的数字必须重算**，并且在交付说明里报告你发现/纠正了哪些数字。

3. 整个任务**最多实跑 2–3 段代码**（跑代码是超时主因）；其余小节用推导、表格、ASCII 图充实。
